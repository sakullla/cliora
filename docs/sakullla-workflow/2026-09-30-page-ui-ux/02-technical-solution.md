# 技术方案

证据见 `01-exploration.md`。需求锚点 R1–R4 都由下面三项决策覆盖。没有需要用户另选的业务分歧。

## ADR 1：前移现有动作簇，不增加交互层

决策：每个当前视图把已经存在的完成动作移到「视图切换」和「阻断状态」之后、长表单或长列表之前。继续使用现有事件处理，不新增命令面板、快捷键设置、密度开关、吸顶遮罩或页面。主操作继续用 `button primary`，次操作继续用 `button`。阻断状态包括应用冲突、恢复失败、目录不可用、未安装导致无法保存，以及浏览器预览横幅；这些留在动作簇之前或同一视图内。路径检测、高级连接、可能计费的诊断、项目选项、导出与项目关联仍放在后面的 `details` 或次级区域。现在直接可见的「启动」「YOLO」「删除」「复制全文」仍直接可见。

页面落点：

- 快速开始：宽度大于 680 时，管理中的工具与项目启动区并列，使 1360×1000 和 900×1000 不滚动即可看到工具状态和至少一个「启动」。640 宽沿用 680 的单列，允许滚动，但「启动」仍在「项目选项」之前。配置切换仍是工具行上的 select，选择后沿现有 `switchProfile` 应用。
- 工具与连接：原生配置、MCP、Skills 的标签留在内容前。命名配置的「保存并使用」和当前配置的「保存」移到标题之下、表单之上；「删除」留在同一簇但不使用 primary。MCP 的「保存到当前 CLI」和 Skills 的「安装到当前 CLI」同样前移到各自面板前部。三个面板继续用 `hidden` 共存，避免卸载草稿。
- 资料库：卡片上的「复制全文」「编辑」保持直接可见。编辑态把「保存」和「复制全文」放在编辑区顶部；「应用到 CLI 原生规则」仍只在已保存且非脏时出现。`LibraryPage` 继续由 `src/App.tsx` 保持挂载。
- 使用记录：保持搜索、工具、收藏的可见顺序，以及详情旁的「在外部终端继续」。导出留在现有 details。不改 `RecordsPage` 的挂载。
- 设置常规：保持管理 CLI、图标、主题、终端、迁移入口的现有顺序。主题选项仍只有跟随系统、浅色、深色。

失败边界：若前移会让某个现在一次可达的控件必须先展开或先换页，则该控件留在原可达性上，只调整视觉主次。不把「确认恢复」再包进 `confirmAction`，避免普通导入多一次确认。

## ADR 2：迁移与同步一次只展开一项

决策：`MigrationSettings` 的操作状态从 `export | import | null` 扩展为 `export | import | webdav | null`。总览始终显示。导出、导入和 WebDAV 连接编辑三者互斥展开；后两者继续用 `hidden` 保持组件挂载，因此预览和未保存连接草稿不因收起而丢失。已连接时，总览可保留「立即同步」和状态，连接表单本身不与导出或导入同时展开。未连接时，总览上的「配置 WebDAV」进入 webdav 操作，而不是一开始展开空表单。WebDAV 的远端删除和替换继续调用 `confirmAction`，对话框仍是 `ConfirmationHost`：取消初始聚焦，Escape 拒绝。

失败边界：互斥只影响展开，不改变导出、导入、同步的成功和失败结果。收起后再进入，已挂载的预览状态保持。

## ADR 3：视口与验证沿用现有壳层

决策：不新增 1360 或 640 断点。大于 680 使用侧栏布局，小于等于 680 使用现有顶栏布局；640 因此落在现有窄布局。验收视口采用现有捕获尺寸 1360×1000、900×1000，以及 `tests/ui/shell.spec.ts` 已使用的 640×760，每种再覆盖浅色和深色。焦点继续用 `style.css` 里已有的 `focus-visible` 轮廓，不新增动效。

正式观察扩展现有 `tests/ui/shell.spec.ts`、`resources.spec.ts`、`records.spec.ts`、`migration.spec.ts`：断言主操作位于长表单或高级 details 之前、可访问名称不变、保存和主题变更不出现对话框、删除或计费诊断仍只有一个取消优先的对话框、迁移三项不同时可见。不断言像素级间距。

## 明确不做

不修改托盘菜单、CLI 写入语义、凭据、同步协议、图标资源或主题变量色值。不重做 `FileConflict` 的内部按钮；冲突块整体仍在受影响视图前部。
