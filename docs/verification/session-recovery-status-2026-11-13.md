# 会话恢复、状态与验证成本优化

日期：2026-11-13；环境：Windows，本地工作区。

## 行为变更

- Git 会话起点随恢复检查点写入 SQLite migration 31。恢复时先安装原起点，再启动 CLI；后续保存不覆盖原值。数据库重开及连续三次会话 ID 变化后，启动前已有修改仍被排除，会话内提交仍计入。旧版本从未保存的起点无法补回，继续使用整个工作区状态，避免把当前 HEAD 当作原起点。
- Codex 活动判断通过适配器读取已解析的当前屏幕底部及标题，区分中断提示、空闲输入框与控制序列重绘。已知忙碌状态不会因工具暂时无输出而超时；自定义或未知布局退回屏幕内容变化判断。该判断仍是界面启发式，不代表任务成功或失败。依据与扩展方式见 [活动适配器说明](../architecture/terminal-activity.md)。
- 设置面板先滚动当前内容，到边界后继续滚动切换相邻分栏；惯性滚动不会连续跳过多个分栏，编辑器和嵌套滚动区域保留自身滚动。
- 活动检查与标题通知按需合并到 80ms；等待终端回放时复用有容量上限的输出队列，移除另一份无界队列。Git 起点读取改用 Arc，避免每次轮询克隆最多 5000 项指纹。

## 测试与捕获精简

保留一个 UI 测试运行器子进程集成用例，将错误分类及重试组合改为直接测试纯函数；CSS 行号扫描改为线性；合并重复对比度断言，删除仅固定源码写法的架构断言，保留真实行为、安全及适配器边界检查。

Node 测试由 195 项调整至 192 项。本机观测：优化前 8.30 秒，优化后 3.40 秒，最终并行单元测试运行中为 3.33 秒；另一次热运行 2.33 秒。数字受缓存和并发任务影响，不是 Rust 或整个应用的提速比例。

桌面窗口配置最小宽度为 720px，默认窗口 1160×780。捕获默认只运行 1360px、浅深两种主题；`--size all` 保留显式多尺寸检查。工作台默认每主题 9 个代表场景，`--full` 才运行完整集合，性能压力测量需 `--performance`。页面总览去除已由独立画廊覆盖的首页及迁移页；`--only settings` 可只捕获设置。

实际捕获结果：设置 2 张，产品页面总览 10 张，工作台 18 张加性能场景 1 张；均无页面错误或横向溢出。图片与 manifest 在本地忽略目录 `docs/verification/session-recovery-status-2026-11-13/`，不将生成画廊批量纳入源码。

## 性能观测

使用相同合成远程流：3 个会话，每会话 20480 行，36 次切换。旧 HEAD 从独立临时目录构建作为对照。最后一次工作台捕获的 GC 后数据如下：

| 指标 | 原版本 | 修改后 |
| --- | ---: | ---: |
| 压力后 JS 堆 | 13,400,828 B | 13,378,916 B |
| 关闭会话后 JS 堆 | 8,781,588 B | 8,786,324 B |
| 关闭后终端数量 | 0 | 0 |
| 事件监听数：运行 → 关闭 | 531 → 365 | 531 → 365 |

稳定堆占用基本一致，不能宣称整体内存明显下降。此次内存改动针对回放延迟时的无界积压和 Git 指纹反复复制。新增回放延迟回归输入超过 1.6MB，确认仍能排空保留的最新输出。

压力阶段累计 TaskDuration：原版本约 38.55 秒，修改后两次约 31.75 / 40.58 秒；并发验证负载不同，不能据此宣称稳定 CPU 提速。
