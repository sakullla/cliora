# 远程会话移除与历史读取验证（2026-11-16）

基线 v0.4.138。目标包括已结束远程会话移除，以及 agy、CodeBuddy、OpenCode、Codex、Claude Code、Pi 的本地/远程历史读取。

## 现场根因与修复

- GNU screen 在无会话时返回退出码 1，输出 No Sockets found 后附有 LF/CR 空行。原探测将回车判成未知，结束流程反复返回 46。只规范化行尾 CR 和空白行，保留权限错误、多条非空诊断与错误退出码检查。新增回归先在旧代码失败；修复后通过。同一只读不存在会话探测在现场由 presence=2 变为 presence=1，未关闭任何用户运行会话。
- agy 1.5.9 原生数据在 ~/.gemini/antigravity-cli，索引使用 conversation_id / workspace_uris，根会话父 ID 为空串。旧目录、旧列名和父 ID 判断导致没有记录；新版 gen_metadata 的 stepIndices 是合法 packed protobuf，而旧 parser 只接受 unpacked，导致所有用量行被跳过。已兼容这些实际结构并保留旧格式。
- 远端原先只声明 Codex / Claude Code 快照，新增其余四类。SQLite 只选择近期会话及相关表/列，保留 WAL 一致性；文件来源过滤、压缩传输、未变化指纹与已解析结果复用。
- 本地 JSONL 丢弃无需消费字段的分配；OpenCode 不解码无关消息/part，缓存未变更索引；Codex 标题目录共享并观察 WAL 更新；agy 索引共享且正文流式读取。

## 实测与边界

本机原生基线：Codex 452 个来源首次约 1524 ms、未变化约 52 ms；Claude Code 6 个来源约 901/1 ms；CodeBuddy 19 个来源约 999/4 ms；Pi 27 个来源约 348/0 ms。本机没有 agy/OpenCode 原生数据，不能将空目录测量当成其本地性能收益。

固定 JSON 样本 2,608,943 字节、20 次解析：完整 Value 分配 786.06 ms，按消费字段解析 326.82 ms，约降低 58%。这是解析器测试构建的观测，不是整款应用的提速百分比。

实际 Linux 远端 agy 已读出 5 段会话、19 条消息和 355 条调用记录，1 段因内容上限标记 partial。首次约 2.2 秒，读取期间仍有会话变化，因此下一次正确重新导出，而非强行使用旧缓存。静态回归样本再次读取只传输 67 字节，并复用同一 Arc 正文。

最终实机复测时远端新增到 6 段会话，成功读取 30 条消息、576 条调用，来源读取错误为 0。批量缺失来源探测后的整页强制刷新约 2034 ms，紧接着的缓存列表读取低于 1 ms（日志整数毫秒显示 0）。这些数字是当前网络与数据规模的观测，不是固定 SLA。

本地复测：Codex 452 个来源首次约 1502 ms、未变化约 10 ms；CodeBuddy 19 个来源约 936/3 ms；Claude Code 6 个来源约 738/1 ms；Pi 27 个来源约 327/0 ms。前后不是隔离 OS 页缓存的严格 A/B，只能作为现场时延观测。
