# 需求：栖点 Cliora — AI CLI 工具管理客户端

日期：2026-09-29

## 一屏摘要

- 目标与使用者：面向同时使用多种 AI CLI 的个人开发者，提供简单、精致、实用、可靠的独立桌面管理中心（R1）。
- 覆盖：Windows、macOS、Linux；Codex、Claude Code、Grok Build、Pi、OpenCode（R2）。
- 工具管理：可选择管理哪些 CLI（R24），安装升级、原生服务商与模型配置、全局和项目方案、MCP、Skills、外部终端启动（R3–R9）。
- 原生配置：每个 CLI 独立保存多份配置，可继承同工具通用配置，支持原生内容编辑及来源查看；未配置工具如实留空（R23）。
- 扩展方式：每个 CLI 独立适配器实现统一接口，新增工具只需注册适配器和能力证据；Kimi Code 可在后续版本按同一方式接入（R25）。
- 日常管理：提示词模板与长期规则、历史会话与外部续聊、本地用量及估算费用（R10–R13）。
- 迁移与同步：配置导出/导入、WebDAV 同步，包含 API 密钥；本机路径重新关联（R14–R17）。
- 关键行为：正常操作直接完成，备份与基础保护自动处理；真实冲突才要求选择，失败可恢复（R6、R16–R18）。
- 成功标准：三平台实际验证五种工具的主要流程；首页与托盘快速切换和启动，视觉与布局围绕日常操作，未知状态如实呈现（R2、R18、R22）。
- 不做事项：内置运行工作台、模型网关、WSL/SSH 管理、余额额度查询；会话和统计不跨设备同步（R14、R19–R21）。

## 完整需求

### R1 独立产品与主要使用场景

行为：交付名为「栖点 · Cliora」的独立应用，项目名为 `cliora`，帮助个人开发者管理自己设备上的 AI CLI，减少查找配置文件、重复配置和工具切换的操作。日常入口围绕工具、配置、项目和可复用资料组织。

适用与失败边界：Cliora 是独立安装和运行的桌面应用，管理用户设备上已有或通过其辅助安装的 CLI。各 CLI 的具体能力与兼容边界按 R2 判定。

验收：

- 用户可独立安装、启动和使用 Cliora。
- 首次打开即可找到工具状态、配置和启动入口，不需要先阅读配置文件格式说明。

### R2 三平台与五种 CLI 的真实支持

行为：首版覆盖 Windows、macOS、Linux 的本机环境，以及 Codex CLI、Claude Code CLI、xAI Grok Build、Pi coding agent、OpenCode CLI。按实际安装版本展示可用能力，保留各工具原生差异。

适用与失败边界：支持桌面系统不代表支持其全部历史版本、处理器架构和 Linux 发行版。发布时须明确列出实际支持并验证的系统版本与架构。每种 CLI 在每个平台都须有可用的安装、配置和启动流程；MCP、项目配置、历史恢复等扩展能力按原生支持情况判定。不以相同界面入口冒充相同能力，也不把“存在文件”直接判为“安装可用”。

验收：

- 发布验收覆盖五种 CLI × 三个平台，在公布的环境中验证安装检测、配置应用和外部启动。
- 工具版本缺少某项能力时，显示简短原因和可行操作，不提供点击后必然失败的入口。
- 未安装、已安装、配置不完整、版本不兼容、检测失败能够区分；单个工具出错不阻塞其余工具。
- 未经过实际验证的组合不能标注为已验证支持。

### R3 安装检测与辅助安装升级

行为：自动发现已有 CLI，显示版本、位置和安装来源；允许用户指定未被发现的可执行文件。对未安装或可升级的工具，提供适用于本机环境的官方安装或升级入口、依赖检查、进度和结果。

适用与失败边界：已有安装应沿用其可识别的安装方式。无法可靠接管的安装，提供可复制的官方操作指引和重新检测入口，不另装一份后假装升级成功。新增依赖或系统授权由明确的安装动作触发，不在普通扫描时执行。

验收：

- 已有安装可以直接接入；自定义路径选择后能够验证并使用。
- 缺少依赖时指出缺少的具体项，并提供下一步；安装完成后重新检测版本和可用性。
- 网络中断、权限不足和安装器失败均显示真实结果及重试入口，不标记为已安装或已升级。
- 升级流程保留已有配置和资料，不擅自终止正在运行的 CLI 会话。

### R4 原生服务商、密钥与模型配置

行为：集中添加、编辑和切换各 CLI 原生支持的服务商、API 地址、API 密钥和模型；提供常用预设和自定义配置；支持多个接口格式的 CLI，可为每份连接明确选择目标 CLI 原生支持的接口格式。能够读取已有配置，将其作为继续管理的起点。原生支持时展示模型参数，例如推理强度；模型优先尝试通过当前供应商接口获取列表，支持搜索、主动刷新与手动填写模型标识。

适用与失败边界：模型与接口的可用组合由目标 CLI 和服务商能力共同决定。不同 CLI 的供应商条目、模型角色和多服务商共存方式不得被强行压成一个全局开关。官方账号登录沿用 CLI 的原生流程，保留其登录状态，不把订阅登录擅自改为 API 密钥模式。

验收：

- 从已有配置接入后，能看到服务商和模型，编辑后由目标 CLI 读取到对应设置。
- 接口格式与 API 地址、密钥、模型一起保存并随配置迁移，写回对应原生字段；选择项依据工具版本能力生成，读取已有配置时保留其格式。更改格式保留已填资料并重新判断模型目录与连接测试能力，不静默转换协议。
- 已知不兼容的接口组合不能作为可用配置应用；未验证的自定义模型明确标为未验证，不伪造验证结果。
- 按当前供应商的 API 地址、认证方式获取模型列表，成功后可搜索并选择，刷新不擅自更换已选模型；列表存在不等于已通过目标 CLI 的调用验证。
- 模型目录获取失败、不支持列表接口或仅有无法用于该接口的原生订阅登录时，清楚说明状态；已有缓存标明更新时间，仍可手动填写模型，不阻塞整个管理界面。
- 可主动测试连接，并区分配置格式正确、服务端可连接和模型请求可用；测试失败提供可理解的原因。
- 需要重新登录时可打开原 CLI 的登录流程；切换自定义服务商后可回到其原生登录使用方式。

### R5 全局默认与项目配置方案

行为：管理全局默认配置及命名方案，并允许项目在 CLI 原生支持的范围内覆盖服务商、模型、MCP、Skills 和长期规则。支持保存、复制、重命名和应用方案；应用前能看清涉及的工具及全局或项目范围。

适用与失败边界：项目配置不能支持的字段要明确显示，不得通过改写全局配置假装实现项目隔离。只改一个工具的配置不得顺带切换其他工具。因项目覆盖、环境变量或其他原生优先级而不能确认最终生效值时，显示来源或不确定状态。

验收：

- 两个项目设置不同的原生项目配置后，各自启动读取正确配置，互不串改。
- 项目未覆盖的项目继承项能与显式覆盖项区分；清除覆盖后回到全局默认。
- 应用全局方案时清楚显示全局作用范围；应用单工具方案后其他工具配置保持一致。
- 不支持的项目能力不能自动退化为全局写入并显示成功。

### R6 配置写入、备份与恢复

行为：普通配置操作直接执行，自动保留可恢复的修改前状态；保留目标文件中不属于本次操作的设置，以及格式允许保留的注释。提供集中查看修改差异和恢复最近备份的入口。涉及导入覆盖、规则覆盖或真实外部冲突时才要求用户作出决定。

适用与失败边界：无法解析的文件不得按默认值重建覆盖。编辑期间发现外部修改时，应重新读取，兼容的修改可以保留，冲突不能静默覆盖。跨多个文件的操作不能留下无法识别的半完成状态；无法自动恢复时须指出受影响项并提供恢复入口。写入成功与运行中的 CLI 已生效是不同状态。

验收：

- 切换模型后，原有无关设置、MCP 和用户自定义内容未丢失。
- 配置格式错误、写入失败或进程中断后，原有有效配置仍可使用或可通过明确入口恢复。
- 外部编辑与当前操作冲突时，双方内容可查看并选择处理；不存在真实冲突的日常修改不反复弹窗。
- 需要重启或新开会话才能生效的变更明确提示，不显示为已影响正在运行的会话。
- 恢复操作可看清目标版本与影响范围；恢复失败不得删除可用备份。

### R7 项目目录与外部终端启动

行为：添加、选择和打开最近使用的项目目录，为项目选择 CLI，并在外部终端中以正确工作目录启动。支持使用合适的默认终端及用户指定的可用终端；首页直接启动可选择普通或 YOLO 模式，按 CLI 原生能力生成相应参数。

适用与失败边界：目录不存在、CLI 不可用或必需配置缺失时，显示直接的修复操作。管理客户端退出后，已启动的 CLI 仍可独立运行。提供启动请求不等于模型连接或后续任务已成功。

验收：

- 包含空格或中文的项目路径在三平台均能正确传入；打开的终端位于所选项目目录。
- 首页启动与会话恢复均可显式选择普通/YOLO 模式，默认普通；YOLO 简短说明会跳过该 CLI 支持的审批或沙箱限制，不支持的工具或版本禁用并说明。所选模式同时反映在实际启动参数和可复制命令中，不通过修改全局配置冒充一次启动选项。
- CLI 启动后读取本机对应配置；关闭管理客户端不终止该 CLI。
- 目录移动后可重新关联，不必删除重建所有项目资料；终端不可用时可以更换并重试。

### R8 MCP 配置管理

行为：对原生支持 MCP 的 CLI，集中查看、添加、编辑、启用和停用 MCP 配置；按其支持范围管理全局或项目配置。可以选择向多个兼容 CLI 分发同一项配置，展示各目标的结果。

适用与失败边界：仅提供目标 CLI 原生支持的连接方式和字段。不把配置启用等同于服务器进程已启动或功能可调用。目标不支持 MCP 时标明能力边界，不自动安装第三方桥接工具补齐。

验收：

- 在兼容目标添加或停用一个 MCP 后，目标 CLI 读取到对应变化，无关 MCP 不被删除。
- 多目标应用能够显示成功、失败和不支持的目标，允许只重试失败项。
- 必填内容缺失时在对应位置提示；本机命令或路径缺失时指出需修复的项。

### R9 Skills 管理与可迁移内容

行为：发现各 CLI 支持的全局和项目 Skills，展示名称、描述、来源和作用范围；支持从本地目录及用户指定的可获取来源导入，向选定的兼容目标安装、更新或移除。可迁移的 Skill 正文及其实际依赖资源作为整体管理。

适用与失败边界：只按目标 CLI 的原生发现和加载规则管理。原生不支持停用的工具，不伪造一个无实际效果的停用状态。只移除用户选定目标的已管理副本，不删除原始来源或其他 CLI 的副本。

验收：

- 导入可用 Skill 后，目标 CLI 能发现其内容与必要资源；内容缺失或格式不兼容时指出原因。
- 同名或外部修改的内容在被覆盖前可比较并选择；更新失败不丢失原来可用的版本。
- 带本机外部依赖的 Skill 明确标出依赖，不能因正文已导入就宣称目标设备可直接使用。

### R10 提示词模板库

行为：保存、编辑、复制和删除日常提示词模板，支持名称、分类和搜索；提供全局模板以及与项目关联的模板，方便在外部 CLI 中使用。

适用与失败边界：模板是由用户主动选择使用的文本，不自动发送到正在运行的 CLI，也不自动变成长期规则。首版不要求复杂的模板编程语言、执行引擎或在线市场。

验收：

- 新建模板后可通过标题或正文搜索找到，一次复制可得到完整正文。
- 项目模板在对应项目中可找到，不与全局模板混淆；编辑和删除只影响选定条目。
- 应用重启后模板及分类仍可用。

### R11 长期规则文件管理

行为：集中查看和编辑 CLI 原生读取的全局及项目规则，例如适用工具的 AGENTS.md、CLAUDE.md 和其他受支持规则入口。可把库中的规则应用到兼容目标，显示实际文件、作用范围及修改差异。

适用与失败边界：各工具对规则位置、层级和内容的理解可能不同，不假定复制到任意位置都能生效。已有规则不由模板导入或同步操作无提示地替换；读写恢复遵循 R6。

验收：

- 编辑目标规则后，相应 CLI 在原生支持的范围内读取新内容。
- 覆盖已有规则时能预览差异，并通过一次确认完成；取消后文件保持原样。
- 多层规则的来源可以辨认；无法可靠确认加载情况时不宣称已经生效。

### R12 历史会话管理与外部续聊

行为：读取本地 CLI 历史，按工具和项目浏览、搜索、查看会话；支持收藏以及将用户选定的会话导出为本地可读资料。支持恢复的会话可一键打开原 CLI，在外部终端继续；详情提供原生恢复会话命令的一键复制，用户可自行粘贴运行；支持选择普通/YOLO 恢复模式，模式语义与首页启动遵循 R7。

适用与失败边界：不在客户端内运行对话。历史记录可能缺失、损坏、格式不受支持或不含完整工具执行内容，应保留可读取部分并说明限制。会话导出供查看，不承诺是可被所有 CLI 导入并恢复的通用会话格式。收藏属于客户端本地资料，不改写原始对话。

验收：

- 可通过工具、项目和关键词找到已记录的会话，查看正文并收藏；再次打开仍保留收藏。
- 同一记录重复扫描不会生成重复会话，单条损坏记录不阻断其他会话浏览。
- 恢复命令可查看并一键复制，包含准确的会话标识与必要的目录切换，按所选平台和终端安全引用路径与参数；复制不执行命令，也不包含 API 密钥。
- 可恢复的会话使用正确会话标识和项目目录打开原 CLI；不支持恢复时明确提示，不能用新建空会话冒充恢复。
- 项目目录缺失时可重新关联后再继续；导出的会话资料可在客户端之外阅读。

### R13 本地使用统计与估算费用

行为：从可获取的本地记录汇总会话数和 token 用量，按工具、模型、项目和日期筛选。记录支持时区分输入、输出、缓存等用量；存在适用价格依据时显示估算费用，并标明价格来源或手动设置及更新时间。

适用与失败边界：不通过新增本地网关收集流量。没有用量记录、价格不明、项目无法归属或时间字段不可靠时，明确显示未知或未归类，不用零值掩盖缺失。估算费用不等于实际账单；订阅费用不能直接由 token 推导。各类 token 不能因统计口径重叠而重复计数。

验收：

- 对已知本地样例，日期和工具等筛选结果与可读取记录一致；重复刷新不重复计数。
- 价格已知时能说明估算依据，价格缺失时仍可显示已有用量，但费用显示未知。
- 页面可看到本次统计的覆盖范围、读取失败或不完整情况，不宣称覆盖未被记录的请求。
- 删除或更新本地源记录后的再次统计能反映变化；会话导出或配置导入不凭空增加本机使用量。

### R14 配置迁移与同步的数据范围

行为：配置导出/导入和 WebDAV 使用统一的可迁移资料范围：服务商与模型设置、API 密钥、命名配置方案、全局默认资料、项目配置定义、提示词模板、长期规则，以及 MCP/Skills 配置与可迁移内容。项目以可重新关联的身份迁移，目标设备映射本机目录与必要的本机依赖。

适用与失败边界：不迁移 CLI 程序和安装状态、项目源代码、终端配置、本机活动方案选择、设备专属绝对路径、日志缓存、会话历史与收藏、使用统计、CLI 网页登录或 OAuth 令牌，以及 WebDAV 连接凭据。本机路径不作为跨设备已可用的路径直接套用；外部文件引用不扩展为对任意本机目录的自动打包。API 密钥的保护由 R17 规定。

验收：

- 迁移到不同系统的设备后，可看到相同的资料和配置方案，并重新关联项目路径。
- 未完成的目录、命令或依赖映射显示待配置；不影响可独立使用的其他导入资料。
- 迁移包和 WebDAV 数据不包含上述排除资料；接收更新不擅自切换当前设备的活动方案。
- API 密钥可以跨设备复用，官方账号登录仍由新设备自行完成。

### R15 简单的配置导出与导入

行为：从一个入口导出全部或选定的 R14 资料，形成可跨设备使用的配置包。导入时一次集中预览新增项、更新项、冲突和路径映射需求；用户可选择导入内容以及应用到哪些本机目标，通过一次确认执行。

适用与失败边界：配置包保护遵循 R17；首版保证本客户端可识别版本的迁移包往返，不承诺自动解析任意第三方管理器备份。无法识别、已损坏或无法解锁的包不能以空配置替换本地资料。未选择本机应用目标的内容只进入客户端资料库。

验收：

- 完成导出后，另一台受支持设备可导入所选资料，中文、分类、规则和 Skill 资源保持完整。
- 导入预览能看见会被覆盖的内容，并可跳过冲突；取消导入不改变已有资料。
- 重复导入同一包不产生无意义的重复条目。
- 成功、失败和仍待配置的项分别列出，已有可用资料在失败后仍能使用；不对每个普通条目重复弹出确认。

### R16 WebDAV 自动同步与冲突处理

行为：配置一个活动 WebDAV 目标，填写连接地址和该目标所需凭据，测试连接后启用同步。启用后自动同步 R14 范围内的变化，提供手动立即同步、最近成功时间及简明状态。可独立合并的修改自动完成，真实冲突集中处理。

适用与失败边界：默认采用 HTTPS。WebDAV 不可达时本地查看、编辑和启动仍可使用，本地修改保留并在恢复连接后同步；自动重试有限，不持续弹窗或无限阻塞。不同设备对同一内容并发修改，或删除与修改相遇时，不得仅凭最后上传时间丢弃一方。远端资料同步到客户端，不等于自动改写本机正在使用的 CLI 配置；对活动资料的远端更新提供一次应用入口，并遵循 R6。

验收：

- 两台设备连接同一同步空间后，在一端新增或修改资料，另一端可接收；正常重复同步不产生重复条目。
- 修改不同资料时自动合并；修改同一内容发生冲突时双方版本可保留、比较并选择，未解决冲突不阻塞无关资料。
- 本地删除能被其他设备识别；离线旧副本不能在重新连接时无提示地复活已删除资料。
- 断网、鉴权失败、远端权限不足和上传中断有可操作提示；恢复连接后可继续，不把失败标为成功。
- 远端格式未知或内容损坏时保留本地有效资料；部分上传不能被其他设备当作完整有效版本应用。
- 用户配置一次连接后，正常同步无重复确认和解锁步骤；可以关闭同步，关闭后本地功能仍可使用。

### R17 API 密钥保护与低负担解锁

行为：API 密钥参与配置迁移与 WebDAV 同步；客户端导出的配置包及写入 WebDAV 的可迁移资料应加密保存，不能以明文配置备份代替加密包。客户端管理的本地密钥采用系统可用的凭据保护能力；界面默认遮蔽，日志和诊断不输出密钥。CLI 自身需要的原生凭据形式按其支持方式提供，不要求 CLI 依赖本客户端持续运行。

适用与失败边界：加密保护必须同时满足跨设备可用与简单操作。WebDAV 的解锁纳入首次连接配置，正常同步自动完成，不强制另设独立同步密码；离线迁移包的解锁纳入一次导出或导入流程，不依赖原设备永久在线或只能访问原设备的系统凭据存储。加密机制、密钥派生和存储方式属于后续技术方案，不在本需求中指定。解锁错误、凭据缺失或数据损坏时保留本地有效资料，不进行破坏性覆盖。

验收：

- 导出文件及 WebDAV 中的配置数据不能直接读取 API 密钥明文；客户端日志、普通列表及错误消息不包含完整密钥。
- 在新设备通过正常首次设置或一次导入流程可恢复 API 密钥并用于对应 CLI；不能仅证明原设备可解密。
- 用户完成首次设置后，应用重启和日常同步不反复要求解锁，不要求额外创建账号或强制维护独立同步口令。
- 凭据更换时不静默丢失已有可用数据；无法解锁时说明需补充的恢复信息，并允许继续使用本地资料。
- 用户仍可主动查看或更换自己管理的 API 密钥；保护措施不阻止正常配置和迁移。

### R18 简单、精致且可操作的界面

行为：默认界面展示五种工具的状态、当前服务商或模型、作用范围及启动入口。视觉与布局以快速选择、切换和启动为中心，配置管理就近展开，避免为了普通切换在多个管理页面间往返。提供浅色与深色主题、统一的文字层级、间距、图标和状态反馈；高级设置收进详情。把“常用操作直接完成、必要保护自动处理”作为交互原则。

适用与失败边界：美观不能以隐藏关键状态、低可读性、密集装饰或不必要动效为代价。正常切换不安排反复确认；真实覆盖冲突、删除资料或需要系统授权时才集中请求选择。界面不得用内部实现术语代替用户能够采取行动的错误说明。

验收：

- 在工具、项目和方案已配置的前提下，从首页切换一个已保存配置或启动一个 CLI，各在 1–3 次点击内完成；操作仍需遵循真实生效边界。
- 一屏能识别当前工具状态和主要操作，常用流程无需手工编辑 JSON、TOML 等文件。
- 工具与连接、资料库、使用记录、设置是主窗口内可直接切换的完整页面；切换后保留必要的选择与草稿。长内容编辑不被限制在多层弹窗中，短选择与必要确认保持简单。
- 三平台在浅深主题、常见显示缩放及键盘操作下，主要控件可见、可读、可聚焦，无关键文字截断或操作被遮挡。
- 网络请求、扫描、安装和同步期间能及时看到进行状态，其他不相关功能仍能操作。
- 失败提示说明失败项及下一步，例如重试、更换路径或重新登录；不会为每次正常操作堆叠警告和确认。

### R22 托盘快速切换与启动

行为：应用运行时提供系统托盘或 macOS 菜单栏入口，不打开主窗口即可为指定 CLI 切换已保存的配置。显示工具、当前配置与作用范围，并可在最近项目中启动 CLI；提供显示主窗口及完全退出的明确入口。主窗口隐藏后仍可使用托盘操作。

适用与失败边界：托盘和主窗口管理同一套配置与状态；切换遵循 R5–R6，不影响其他工具或误改作用范围，不宣称改变已有会话。真实冲突或需要补全信息时直接打开对应处理界面。运行环境无托盘宿主或托盘不可用时，明确说明并保留可访问的主窗口，不隐藏成无法找回的进程；已发布支持环境须实际验证托盘功能。

验收：

- 在工具与配置已就绪时，从托盘入口到完成指定工具的已保存配置切换最多 3 次点击，无额外普通确认，也无需先打开主窗口。
- 可辨认当前工具、选中配置及全局/项目范围；切换成功后再次打开托盘与主窗口看到一致结果；失败时保留原选中状态并能直接处理。
- 可选择最近项目并在外部终端启动；路径失效时提供重新关联入口，不偷偷改为其他目录。
- 主窗口隐藏后仍能切换和重新显示窗口；完全退出后应用停止运行，但已启动的外部 CLI 不被终止。
- 在三平台公布的桌面环境中验证菜单、键盘操作与明暗外观；托盘不可用时仍能正常访问并退出应用。

### R23 每工具多份原生配置与通用配置继承

行为：每个 CLI 可独立保存零份、一份或多份命名原生配置，例如同一 Codex 或 Claude Code 的日常与备用配置。提供新建、复制、重命名、编辑与切换；可查看和编辑该 CLI 的原生配置内容，同时保留适合日常使用的表单。每个工具可以维护自己的通用配置，各命名配置可选择继承并覆盖同工具通用字段。编辑时可查看本配置内容、继承来源及合并后的结果。

适用与失败边界：这里的通用配置是同一 CLI 内可复用的配置基础，与 R5 的原生全局/项目层级不同；不能让 Codex 通用配置直接套到其他工具。命名配置的数量、当前选择与工具安装状态独立，未配置的 Grok 等工具不预填为可用配置。仅在原生支持的范围应用，既有未知字段遵循 R6 保留；格式错误不得覆盖原生文件。CLI 可能分多个配置文件，编辑和应用须保留其原生分工，API 密钥与网页登录身份遵循 R4/R17。

验收：

- 为同一 Codex 保存两份原生配置并反复切换，名称、差异与选中状态可辨；Claude Code 可独立做同样操作，互不改写。
- 尚未创建配置的工具显示“未配置”和添加入口，不显示假当前模型；其他已配置工具仍可正常切换与启动。
- 某命名配置启用继承后，未覆盖字段使用本工具通用值；显式覆盖后使用本配置值，清除覆盖后恢复通用值；关闭继承后能看清不再继承的影响。
- 修改通用配置时能看见受影响的命名配置；未启用继承的配置不变，已有显式覆盖仍保留，不影响其他 CLI 的通用配置。
- 原生编辑与表单针对同一份内容，切换视图不丢失未提交修改；合并结果能区分通用字段与覆盖字段。非法原生内容保留编辑文本并指出错误，不写入有效原生配置。
- 主窗口和托盘均可选择该 CLI 已保存的命名配置；原生多文件应用失败、外部冲突与恢复遵循 R6，切换不能冒充运行中会话已生效。

## 不做事项

### R19 不内置 CLI 运行工作台

行为：首版不提供客户端内的终端、持续对话、任务执行或代理编排工作台。

适用与失败边界：历史会话查看和资料管理属于当前范围；实际执行和续聊通过原 CLI 的外部终端完成。

验收：

- 从客户端启动或恢复会话进入外部终端；查看历史不会在客户端中自动执行其内容。

### R20 不提供模型网关与协议转换

行为：首版不代理模型请求，不提供 API 协议转换、自动模型路由、故障转移或跨 CLI 复用官方订阅令牌。

适用与失败边界：服务商必须能被目标 CLI 原生使用；API 密钥可以按 R14 迁移和复用，不等于转换服务协议或共享网页登录身份。

验收：

- 已配置的 CLI 可在管理客户端退出后自行连接服务商。
- 不兼容的服务商接口明确显示限制，不通过后台自动部署代理补齐。

### R21 其他首版范围边界

行为：首版不管理 WSL、SSH 或远程机器中的 CLI，不查询服务商余额或订阅剩余额度，不建设团队账号、集中权限体系及在线资源市场。

适用与失败边界：三平台的本机管理、用户自有 WebDAV 和本地用量统计属于当前范围；CLI 自己支持的远程能力不代表管理客户端已支持对应环境。

验收：

- 产品验收不以读取 WSL 或远程配置替代某平台的本机支持。
- 用量页面仅展示本地统计及明确标注的估算，不显示未经查询的余额或额度。
- 使用本地管理与自有 WebDAV 不要求注册本产品账号或组织。

### R24 选择管理的 CLI

行为：设置中可勾选管理哪些 CLI，首页、工具页及托盘同步只展示选中的工具；用户可随时恢复管理。

适用与失败边界：取消管理不卸载 CLI、不删除原生配置、命名配置和既有记录，不改变正在运行的会话。允许全部取消，空状态提供返回设置的入口；首次使用默认列出五种受支持工具供选择，未安装、未配置状态如实显示。

验收：

- 取消一个 CLI 后，首页、工具页和托盘一致隐藏；重新勾选后原有配置仍在。
- 全部取消后显示可恢复的空状态，设置仍可访问。
- 换设备恢复可迁移资料时包含管理偏好，不假定新设备已安装这些工具。

### R25 独立 CLI 适配器与后续扩展

行为：CLI 差异通过统一适配接口表达，Codex、Claude Code、Grok、Pi、OpenCode 各有独立实现。接口覆盖身份与安装检测、版本能力、原生文件角色与解析/写入映射、认证方式、模型目录与连接测试能力、外部启动/恢复参数，以及后续 MCP、Skills、规则和历史记录能力；共享层负责事务、持久化、迁移、托盘和界面编排。新增 Kimi Code 等工具时，以新增适配器、注册信息和版本化验证样本接入，不把其特例散落到各页面或共享服务。

适用与失败边界：这是代码层面的可扩展能力，不要求首版实现 Kimi Code、运行时插件市场或让用户编写适配器。新增工具仍须按 R2/R4 的实际版本和平台证据验证，不能因为实现接口就宣称兼容。现有五工具的行为、资料 ID、配置和切换结果在重构后保持一致。

验收：

- 五个工具分别由自己的模块实现共同契约；共享流程不以反复增加工具名分支来决定配置、认证和启动行为。
- 用一个仅在测试中注册的示例适配器验证注册、能力显示、配置读取/应用与启动参数编排，无须修改现有五个适配器或共享流程。
- 未注册或版本能力未知的工具不被伪装为可管理；新增适配器失败不影响现有工具。
- 文档说明日后接入 Kimi Code 所需的模块、注册、版本样本和平台验收步骤。
