# ACP v1 与 v2 Preview 兼容及工作台能力补齐

2026-11-28 · 产品需求 · 现状基线 `02707f25`

## 一屏摘要

工作台用户应能在本机或选定的远端主机连接 ACP agent，发送任务，判断前台与后台进度，查看子代理，回答问题，并在断线后继续原会话。
交付范围包括 v1 已识别的全部缺口，以及官方 v2 Preview 基线的客户端实现。版本与能力按连接协商，已有 v1 安装和历史会话继续可用（R1–R4）。
用户应能区分停止工作、撤回单个请求、关闭标签和删除历史；授权、登录与 Pi 的选择题和自由回答各有明确结果（R5–R8）。
父子会话、工具、终端、计划和媒体按来源展示；会话支持多目录、系统提示与 MCP 配置（R9–R13）。
远端支持 SSH、HTTP 和 WebSocket，文件、执行、凭据和安装归属所选目标（R14）。HTTP／WebSocket 按独立的传输规范验收。
以 2026-11-28 官方文档为基线。协议、真实 agent、桌面交互和多会话资源占用分别取证；单次握手不能证明某项功能可用（R15）。

## 完整需求

### R1 按连接协商协议与能力

Cliora 按本次连接启用的版本发起握手，识别 v1 的客户端／agent 字段和 v2 的 `info`、`capabilities`、对象型能力标记。协商结果决定后续报文、可用操作及错误处理。工作台能查看实际协议版本、agent 身份和本连接的限制。只有能在该目标履行的能力才可声明。

**验收**　同时连接仅支持 v1 的 agent、支持双版本的 agent 和仅支持 v2 的 agent，分别完成建会话、发消息和停止。旧 agent 正常选回 v1；遇到旧实现拒绝新版握手时，可在创建任何会话前重试 v1。双方无共同版本时给出诊断；认证失败和业务错误不能触发降级重发。按对应 schema 处理必填字段、未知扩展和未知请求，单个扩展不能使其他会话断开。

### R2 会话环境、多工作目录、系统提示与 MCP

新建、加载或恢复会话时，用户可核对主目录、附加工作目录、系统提示和本次提供的 MCP 服务。按 agent 的声明启用系统提示的追加或覆盖模式；首条用户消息独立发送。恢复时重发本次完整的附加目录和 MCP 集合。按版本编码 MCP 传输类型，包括 v1 的 stdio、HTTP、SSE 和 v2 的显式 stdio、HTTP；校验名称、路径及目标主机。

**验收**　以两个工作目录、一个 MCP 服务和系统提示启动会话，检查 agent 收到的参数；删除一个目录和该服务后恢复，旧项应消失。遇到相对根目录、重名服务、v2 中的旧 SSE 配置，或 agent 未声明的覆盖模式，指出具体配置并保留输入。用户须能看到哪项配置未应用。

### R3 会话列表、关闭、删除与恢复回放

v1 按声明使用 list、load、resume、close、delete；agent 声明 `session/close` 时，关闭活动会话应通知 agent 释放资源，并清理 Cliora 的恢复记录。v2 支持会话基线中的 list、resume、close，按 `replayFrom` 请求回放，删除历史按独立能力开放。保留会话与原主机、目录、账号及审查基线的关联。

**验收**　分别验证分页、完整回放和从受支持位置继续、关闭后保留可恢复的原生历史，以及明确删除后的不可恢复状态。v2 新建或恢复后，以响应中的配置和命令列表替换旧列表。回放与实时输出交叠时消息只出现一次，旧授权卡不能重新作答。握手失败留下的标签和已退出的会话均可关闭。恢复目标不存在时给出原因；新开对话须由用户明确选择，不能重发原首条提示。

### R4 v2 消息插入、前台状态与后台任务

v1 沿用 prompt 返回轮次结果的语义。v2 收到 `session/prompt` 返回的 `messageId` 后确认用户消息已插入，再依据 `state_update` 展示运行、等待操作、空闲或状态未知。跟踪 agent 主动开始的工作和列出的后台工具、终端、子会话。支持以协议幂等键关联同一次提交的重试。

**验收**　让 agent 先确认插入，再输出消息，最后报告前台空闲，同时保留一个后台任务。界面应能分别回答“消息发出了吗”“前台结束了吗”“还有什么在运行”。后台列表缺失与明确报告空列表有不同含义。断线发生在插入确认前后时分别验证恢复，不能重复启动任务或把未知结果标为成功。

### R5 分别取消请求、轮次和具体工作项

支持按 JSON-RPC 请求 ID 收发 `$/cancel_request`；停止前台轮次使用 `session/cancel`。v2 对单个工具或终端的取消、两个版本对子代理的取消，均只在对象声明相应能力时开放。停止请求发出后，保留必要的最终更新，按对应版本的确认信号结算结果。

**验收**　并发挂起两张卡，只撤回其一；该卡立即失效，另一张仍可回答。覆盖取消与回答同时发生、重复取消、v2 消息插入前后取消，以及关闭尚有待答请求的会话。一次请求只产生一个终局答复；取消一个工作项不能连带取消同级任务。

### R6 协议认证、终端登录与退出

支持 v1 的 `authenticate` 及能力门控的 `logout`，支持 v2 的 `auth/login`、`auth/logout` 和新版认证描述。协议驱动与终端驱动的登录分别执行。终端登录在正确主机和目录复用已选 agent 的启动程序，按版本处理该方法的参数和环境。确认界面标明程序、主机和登录方式；远端报文不能替换已配置的可执行程序，参数按原边界传入，禁止拼成可解释的 shell 命令。用户应能区分登录完成、登录被取消、凭据失效与配置错误。

**验收**　至少覆盖原生登录、显式绑定账号和远端账号。已有可用登录的 PTY 与 ACP 解析到同一身份环境；普通模型／配置错误展示原始原因。Kimi 的终端登录路径实际打开可输入的 `kimi acp --login` 终端；登录后可回到正确目录建立对话。退出前说明目标与影响，完成后如实更新登录状态，不牵连其他主机或账号。

### R7 区分执行授权、用户选择和自由回答

支持 v1 权限请求和 v2 的标题、描述、可选 `subject`；按版本支持会话或请求范围内的结构化表单，保留接受、拒绝和取消的区别，并按该版本校验输入字段。执行授权可按已选模式处理；业务选择、确认意见和自由输入始终由用户作答。普通模式和 YOLO 模式都应展示问题、可答选项和取消操作，按原请求 ID 回传结果。

**验收**　用截图对应的 Pi 流程实测：选择第二项时回传第二项的原始选项 ID；取消后不启动研发；多选逐步提问后只提交最终选择。选择“其他”时应能输入并交回自定义文本，不能在 Pi 与选择菜单间循环。`pi-acp 0.0.35` 会在桥内取消部分输入请求，因此这项交付须包含能传递自由输入的桥接路径，并覆盖旧桥的识别、提示与升级／切换；仅在 Cliora 画出输入框不算完成。

### R8 URL 提问与外部交互完成

支持 URL 模式的 `elicitation/create` 和 `elicitation/complete`。在打开前展示请求来源、目的站点和操作说明；用户可接受、拒绝或取消。按连接和 `elicitationId` 关联外部流程。用户同意打开、浏览器已打开和 agent 确认完成分别呈现。

**验收**　同一时间在两个会话发起请求，完成其中一个只更新对应条目。覆盖不安全 URL、浏览器打开失败、外部流程未报告完成、重复完成以及断线后的迟到回调。凭据或回调里的敏感数据不得进入会话正文、日志、导出或远程上下文。

### R9 子代理的观察、交互与独立取消

v1 声明 `subagents` 后、v2 建立会话后，处理子代理登记、嵌套关系和所属会话的更新。可展开查看子代理的目录与附加目录、任务状态、消息、工具、计划、配置和用量；保留会话间消息的发送方与接收方。子代理的问题和授权在所属子会话下回答；当子代理公布或撤回取消能力时，对应操作同步更新。

**验收**　交错运行两个子代理及一个孙级子代理，让父子使用相同的工具调用 ID。输出、用量和授权不串线；取消一个子代理后，父会话与同级子代理继续运行。恢复时区分历史子代理和本次连接重新公布的活动子代理。需要手动委派时，经父 agent 或它明确声明的桥接能力发起；原生协议没有通用的“创建子代理”或“给子代理发 prompt”方法。对只通过父会话报告结果的桥，界面如实说明可观察范围；Pi 独立子代理展示须以真实桥接事件验收。

### R10 计划、会话通知与上下文压缩

v1 保留整份 `plan` 清单，并在协商后支持按 ID 的 `plan_update`、`plan_removed`、会话 `notice`、`compaction_update` 与 `compaction_summary_chunk`。v2 按自身规则处理这些事件。展示清单或 Markdown 计划、变更、压缩进度及摘要，并标明所属会话。

**验收**　建立两份计划，更新一份、移除另一份；回放后结果与实时观看一致。压缩摘要分块到达、失败或中断时，条目仍在正确的时间线位置，能区分处理中、已完成和结果未知。agent 发出的标准通知与 Cliora 本地错误应能区分。

### R11 配置、斜杠命令和权限卡随版本更新

在 v1 握手声明已实现的布尔配置能力，兼容已有模式、选择器及配置更新。v2 按 `configId`、`groupId` 和类型处理配置，模式通过配置选项呈现；加载初始化／恢复结果中的配置与可用命令，并应用动态更新。权限卡须说明待授权的操作及关联对象，允许只拒绝当前请求。

**验收**　同一 agent 在两个版本下均能切换模型、推理档位和布尔开关。同一逻辑选项只显示一次，agent 拒绝修改后恢复已确认值。恢复后已移除的配置和命令不能继续使用；子代理命令不会出现在父会话输入框。收到未知类型时保留本次会话和已支持控件，并提供可读诊断。

### R12 音频、图片、资源与消息回放

支持向声明音频能力的 agent 发送音频，并呈现工作台支持的入站媒体；对工具返回的图片提供真正可看的预览。保留文本、Markdown、图片输入、资源链接与嵌入内容的现有路径。v2 以消息 ID 处理整条消息的新增／替换及后续增量，区分用户、agent、思考和会话间消息。

**验收**　覆盖可播放音频、可查看的工具图片、缺少能力、超限、损坏和未知格式。发送失败保留草稿。含媒体的会话重放后消息不重复，历史媒体不会自动播放；切换或关闭会话后释放解码资源。未经允许，不得因解析远端消息而读取本机路径。

### R13 v2 工具流、差异和 agent 所有的终端

按工具 ID 合并 `tool_call_update` 和 `tool_call_content_chunk`，首次更新可创建条目，后续更新按字段区分省略、清空和替换，处理暂停、取消及其能力变化。展示结构化 diff，包括新增、修改、删除、重命名、复制、二进制和仅有局部片段的变更。处理 `terminal_update`、`terminal_output_chunk`，按终端 ID 关联字节输出、快照和退出信息。v1 继续支持已声明的客户端文件与终端服务；v2 的展示终端由 agent 拥有。

**验收**　流式输出跨越字符边界，恢复时存在终端快照和后续增量，最终内容正确且仅出现一次。区分空文件与已删除文件、暂停与完成。处理 v2 展示事件不会在本机执行命令或修改文件。工具、终端与前台轮次的结束状态分别核对。

### R14 SSH、HTTP、WebSocket 与主机隔离

保留本机和 POSIX SSH stdio；新增可配置的 HTTP 和 WebSocket ACP 服务端点，明确显示所选主机、连接方式、认证状态和错误。HTTP 与 WebSocket 作为产品要求交付，依据官方远程传输提案记录采用的版本，与会话内 MCP 的 HTTP／SSE 配置分别验收。

远端 v1 agent 如需客户端文件或终端服务，操作必须落在选定远端主机的授权范围内。仅在目标具备可验证的读写或执行通道时发布对应能力；仅给出 ACP URL 的目标不会因此获得本机资源。SSH 依赖缺失时显示目标主机与安装内容，用户确认后在该主机安装并继续。

**验收**　分别以本机、SSH、HTTP 和 WebSocket 完成协商、发消息与停止；验证有无目标侧文件／终端能力两种情况。让远端与本机存在同名路径，检查实际访问主机。覆盖证书或主机身份异常、凭据过期、传输中断、重连和重复投递。重连不得重发已执行的写入，远端不得取得本机 secret broker 令牌或受管凭据。

### R15 交付证据与现有工作台回归

交付时提供“版本 × 能力 × agent／桥版本 × 主机／传输”的支持矩阵，分别登记协议夹具通过、握手通过、真实交互通过、上游缺失及未验证。Rust／TypeScript 契约同步；新增供应商特例归适配器，事件归属、取消、文件和进程生命周期留在共享服务。

**验收**　每项条款均有对应证据。用可控对端覆盖正常、拒绝、取消、断线、重复、回放与未知消息；用真实兼容对端各完成一次 v1 和 v2 的建会话、交互及恢复。复现 Pi 提问、子代理、Kimi 登录终端、Codex 正确桥接和 ACP 会话的 Twiglane 审查返回。沿用已有 40 个终端各输出 1600 行的内存回归，并验证多个含工具流、媒体和子代理的 ACP 会话关闭后能回收资源。浏览器堆、桌面进程占用和 agent 子进程占用分别记录；需要真实账号或推理费用的验证按仓库已有约定执行。

## 范围边界与外部依赖

- 验收对象是 Cliora **作为 ACP 客户端**的行为，以及为上述实际场景所需的适配器／桥接支持。“支持”须注明由哪一端实现、如何触发、验证到了哪一步。
- v2 Preview 以本次核对的基线 schema 和迁移说明为准。仅出现在 unstable schema 的实验方法不自动计入；如远程传输提案或上游桥在开发期间变化，记录所用版本与差异，保留上述用户场景作为验收目标。
- Pi 暴露子会话和自由输入需要桥接端配合。开发时须核实可复现的发行版本；交付记录要说明可用版本和取得方式。上游只在父会话输出文字时，不能凭文本猜测子代理身份并据此发送授权或停止指令。
